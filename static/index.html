The problem

Major dependency upgrades often break working code with deprecated APIs, removed methods, and changed runtime behavior. Fixing these issues requires developers to spend hours reading through changelogs and debugging by trial and error.

How it works
1

Run tests on new version

Run your tests on the new version and see what breaks in an isolated sandbox environment.

2

Look up migration guide

Look up the official migration guide using targeted web search to extract exact replacement rules.

3

Patch the code

Patch the code, never the tests. Test files and configurations remain strictly protected and unmodified.

4

Verify and repeat

Re-run the tests and repeat until they pass or a limit is reached, then review the diff.
